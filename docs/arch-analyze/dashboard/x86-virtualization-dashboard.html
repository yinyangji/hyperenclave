x86 虚拟化机制三大支柱
用硬件在 ring0 之上再造特权夹缝 —— Intel VMX root/non-root 与 AMD SVM host/guest
核心结论
x86 原不满足 Popek-Goldberg 可虚拟化条件（17 条敏感指令在 ring3 不 trap）；VT-x/SVM 引入比 ring0 更高的运行模式，敏感操作自动 VM-Exit 陷入仲裁。三大支柱：CPU 虚拟化 + 内存虚拟化 + IO/中断虚拟化，缺一不可
Ⅰ CPU 虚拟化
VMX / SVM
guest 敏感操作→ VM-Exit →hypervisor 仲裁
  • VMX root/non-root 双模式，VMCS 三区（guest/host/control）
  • VMLAUNCH/VMRESUME 进入，VMREAD/VMWRITE 读写字段
  • AMD SVM host/guest，VMCB + VMRUN，clean bits 加速
  • 通用寄存器不自动保存，须入口汇编处理

VM-Exit 生命周期陷入—仲裁—恢复
一次敏感操作如何从 guest 陷入 hypervisor 再返回 —— 硬件与软件的分工边界
核心结论
VM-Exit 时硬件保存 guest-state 到 VMCS、加载 host-state，但通用寄存器 RAX–R15 与浮点状态须软件入口汇编保存；按 exit reason 分发仲裁后 VMRESUME 重入 —— 这正是 VMX hypervisor 入口用 naked function 手写保存协议的根本原因
① 陷入 · 保存
VM-Exit
敏感指令/事件→ 硬件切换 →host RIP
  • 硬件保存 guest-state（RIP/RSP/CR/段）到 VMCS
  • 加载 host-state，置 exit reason + qualification
  • 软件入口汇编 push RAX–R15、切 host 栈
  • AMD：#VMEXIT 保存 VMCB save 区
