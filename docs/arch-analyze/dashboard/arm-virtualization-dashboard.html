ARM 虚拟化机制异常级别 EL2
在 EL0–EL3 体系里专设 EL2 给 hypervisor —— trap + Stage-2，而非独立运行模式
核心结论
ARM 用异常级别表达特权：EL2 专给 hypervisor，宿主/guest 跑 EL1/EL0，敏感操作经 trap 陷入 EL2；VHE 让宿主内核直接跑 EL2 化身 hypervisor。与 x86 root/non-root 正交模式不同，ARM 复用统一异常机制
Ⅰ 异常级别模型
EL0 – EL3
EL0/EL1 guest→ trap →EL2 hypervisor
  • EL0 用户、EL1 OS 内核、EL2 hypervisor、EL3 Secure Monitor(ATF)
  • 安全状态：Non-secure/Secure（ARMv9 加 Realm/Root 四世界）
  • 异常进入置 ELR_EL2/SPSR_EL2，跳 VBAR_EL2 向量
  • 敏感操作以同步异常 trap 到 EL2
EL2 专用VBAR_EL2
Ⅱ VHE 执行模型
Virtualization Host Ext
宿主内核→ E2H=1 →直接跑 EL2
  • non-VHE：宿主 EL1、hypervisor EL2，切换频繁
  • VHE（ARMv8.1）：HCR_EL2.E2H=1，宿主内核即 EL2
  • Linux KVM 默认 VHE，消除 EL1↔EL2 开销
  • host 内核可就是 hypervisor 本身
EL2&0 regime
Ⅲ 关键 EL2 寄存器
Control Registers
HCR_EL2→ trap 控制 →ESR_EL2
  • HCR_EL2：trap 控制 + Stage-2 使能 + E2H
  • VTTBR_EL2：Stage-2 基址 + VMID
  • ESR_EL2：异常综合（EC + ISS）
  • HPFAR_EL2：故障 IPA（>>4）
ESR_EL2.ECHPFAR_EL2
一句话：ARM 把虚拟化嵌进统一异常级别，EL2 即枢纽图 1 · 特权模型
trap 到 EL2 生命周期陷入—仲裁—返回
guest 敏感操作如何经同步异常陷入 EL2 再 ERET 返回 —— ESR_EL2.EC 标识原因
核心结论
guest 命中 HCR_EL2/CPTR_EL2 trap 位或 Stage-2 fault，硬件保存 ELR_EL2/SPSR_EL2、置 ESR_EL2（EC+ISS）、FAR/HPFAR，跳 VBAR_EL2；软件保存通用寄存器、按 EC 分发仲裁，ERET 返回 —— 与 x86 一样不自动保存通用寄存器
① trap · 保存
Exception to EL2
敏感操作/fault→ 硬件 →VBAR_EL2
  • 命中 HCR_EL2/CPTR_EL2 trap 位或 Stage-2 fault
  • 硬件保存 ELR_EL2/SPSR_EL2
  • 置 ESR_EL2（EC+ISS）、FAR_EL2/HPFAR_EL2
  • 软件入口保存 guest 通用寄存器
ESR_EL2.EC
② 分发 · 仲裁
Dispatch by EC
EC→ handler →仿真/建映射
  • EC=0x16 HVC（hypercall）
  • EC=0x24/0x20 Data/Instruction Abort
  • EC=0x18 MSR/MRS 系统寄存器访问
  • 仲裁：仿真寄存器 / 处理 Stage-2 fault / 转发
HVC · Data Abort
③ 返回 · 续跑
ERET
恢复通用寄存器→ ERET →guest 续跑
  • 软件恢复 guest 通用寄存器现场
  • ERET 恢复 ELR_EL2/SPSR_EL2
  • 回到 guest EL1/EL0 续跑
  • 对照 x86 VMRESUME 重入
ERET
一句话：x86 看 exit reason，ARM 读 ESR_EL2.EC —— 同构的陷入仲裁图 2 · trap 生命周期
关键子系统翻译 · 中断 · DMA · 机密计算
Stage-2 二级翻译、GICv3/v4 中断、SMMU DMA 隔离，与 ARM CCA 四世界机密计算
核心结论
Stage-1/2 与 x86 EPT/NPT 同构；GICv3/v4 + List Register + vLPI 直投完成中断虚拟化；SMMUv3 隔离设备 DMA；ARM CCA 用四世界 + GPT + RMM 提供虚机级机密计算
