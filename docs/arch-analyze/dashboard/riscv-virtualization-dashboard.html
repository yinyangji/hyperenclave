RISC-V 虚拟化机制H 扩展 HS-mode
把 S-mode 增强为 HS-mode 给 hypervisor，下开 VS/VU 给 guest —— 复用统一 trap/CSR
核心结论
基础 RISC-V 只有 M/S/U；H 扩展把 S 增强为 HS-mode 跑 hypervisor，新增 VS/VU 跑 guest。既非独立模式（x86）也非专设级别（ARM），而是叠加到既有 S-mode、复用同一套 trap/CSR，规范极简可组合
Ⅰ 特权模式
M / HS / VS / VU
VS/VU guest→ trap →HS hypervisor
  • M-mode：SBI/固件（最高特权）
  • HS-mode：hypervisor（S + H 扩展）
  • VS-mode guest 内核、VU-mode guest 用户
  • SBI 提供固件服务（类比 ARM EL3/PSCI）

trap 到 HS 生命周期陷入—仲裁—返回
guest 敏感操作或 G-stage fault 如何陷入 HS-mode 再 sret 返回 —— scause + hstatus.SPV
核心结论
VS/VU 敏感操作或 G-stage fault（未委托）trap 到 HS，硬件置 scause/htval/htinst、hstatus.SPV=1，保存 sepc/sstatus，跳 stvec；软件保存通用寄存器、按 scause+SPV 分发仲裁，sret 返回。特色是异常/中断委托（hedeleg/hideleg）减少不必要 exit
